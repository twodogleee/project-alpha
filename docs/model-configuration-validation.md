## 打包应用与页面验收

新 JAR 临时监听 18081。先对开发 schema 执行新增 V2，验证健康检查为 UP、公开配置 revision=0；没有保存开发模型设置，也没有改写原项目。开发 schema 的模型配置表仍为空，首次页面使用后端环境默认值。

完整页面验收使用另建的随机 `alpha_model_smoke_<UUID>` PostgreSQL schema、独立主密钥和 18082 本机模拟平台。模拟 API Key 不具备真实平台权限，模拟结果明确写有本机测试来源。

通过浏览器验证以下流程：

1. 打开模型配置弹窗，需求输入保持原样；切换平台，输入自定义模型名称与地址。
2. 显式连接测试成功，表单仍未保存，项目列表没有新增测试项目。
3. 未保存时关闭会提示保留编辑；选择继续编辑后内容仍在。
4. 保存成功显示配置版本及“API Key：已加密保存”，新密钥输入清空，工作台运行信息更新。
5. 使用新配置生成并保存需求草稿，得到本机模拟结果，来源为真实模型调用路径。
6. 需求正文存在未保存修改时打开配置、保存 demo 并关闭，正文编辑保持；旧草稿仍标记 AI 来源。
7. 两窗口先后保存，旧窗口收到冲突且保留输入，重新载入前仍保护未保存编辑。
8. 同目标 API Key 留空可以重新切回真实模式。停止并重启同一 JAR 后，读取相同配置版本，密钥不回显，再次连接测试成功。

数据库只读检查确认模拟凭证以带版本的密文保存，私有主密钥权限为 0600。测试输出未出现上游回显的模拟凭证；源码检查未发现实际凭证配置值，JAR 未包含 `.env` 或本地主密钥文件。

本次临时 JAR、模拟平台和测试标签页均已关闭；页面验收 schema 已清理。原有 18080 后端及 5178 前端开发进程没有重启。加载本次后端代码需用户重启开发启动命令一次；之后页面配置保存即时生效。
