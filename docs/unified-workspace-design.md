# 会话直接生成和编辑同一份 PRD

日期：2026-10-14。作者：Andersen。范围：单人桌面产品，原型后续接入。本设计替代此前“需求采集 → 确认需求 → 生成 PRD”的主交互。

## 用户流程

新建会话后直接打开功能型 PRD 草稿（templateVersion=2），默认绑定管理系统模板第一版，可在文档中切换为 App / 小程序、通用产品或未删除的已发布自定义模板。基础结构为产品概述与核心流程、功能模块与页面、全局约定与跨模块规则、非功能要求和待确认事项，各模板调整名称、写作提示、默认页面类型和必要章节。左侧为模块与页面目录，中间默认阅读当前文档，右侧为可收起的讨论；未知章节保持空白并集中在待补充区，允许逐步完善。没有独立需求概要表单、需求确认按钮、重新生成整份文档按钮或返回需求采集阶段的操作。现行模板管理、版本及删除恢复契约见文末“受限动态模板”和“模板删除与恢复”。

会话默认讨论全文，也可聚焦目录中的整体章节、模块、页面及其正文部分。模型返回确实需要变更的章节完整文本；业务规则变更可同步调整流程、异常、验收等关联章节。后端保留未涉及章节，在助手回复后说明实际变化的章节。

正文输入停顿约 700ms 自动保存。发送消息、下载、定稿和离开页面之前刷完保存队列。保存期间继续输入会排队，迟到保存响应不替换新输入；冲突保留本地稿，明确重新载入后才替换。

待确认事项属于 PRD，可注明对应章节，用户通过聊天回答或直接修改。模型只在问题有结论时更新对应章节并移除问题。可选设计建议单独列出，模型只能新增建议；“采纳到文档”将建议原文追加到对应章节，“忽略”只移除建议。两种动作都形成文档修订和决策事件。未采纳建议不属于正式范围，不阻止定稿。

“确认 PRD 定稿”是唯一正式确认动作，服务器按文档绑定的模板版本检查整体必要章节、至少一个模块及其页面、模块必要章节、页面类型对应的必要章节、无待确认事项和已知模板占位符，并拒绝模型任务执行期间定稿。无需存在需求评审基线。“继续编辑”回到同一文档，旧定稿版本不可变。原型只显示后续接入。

历史版本内可以查看草稿快照和不可变定稿版本，支持分页。最近正文变更可撤销为新修订；建议决策不通过普通撤销逆转。Markdown 下载区分草稿和定稿，并标识本地模板、人工或真实模型来源。

## 数据、模型与并发边界

- 继续复用项目、会话、需求版本、生命周期产物、任务与历史表，不另建第二份当前 PRD。需求版本仅作为现有文档容器，旧目标/范围保留为历史来源；新的 PRD 定稿目标和范围直接取文档正文。
- Flyway V8 为 `version_lifecycle_state` 添加 `direct_prd` 和 `proposals_json`。未转换旧记录默认保持原模式；打开活动会话后在项目锁内转换一次，归档和取消对象不隐式转换。
- `WORKBENCH` 任务固定 PRD、建议列表、版本修订、产物修订、项目背景和有界近期消息。模型在事务外调用，结果与助手消息在同一事务保存。当前稿变化则保留未应用候选，不强制覆盖。
- `WorkbenchWorkflow` 通过真实 Graph 执行结构化编辑。复杂数据以 JSON 文本穿过 Graph 状态复制，凭证只存在调用期私有运行对象。任务持久化仍不代表 Graph 检查点恢复，服务重启中断遗留任务。
- 模型 `modules` 仅描述结构增量（模块、页面的新增、改名、类型变更、显式删除），未列出的同级对象不删除。`sections` 定点更新既有全局键、`module:模块ID:章节键`、`page:模块ID:页面ID:章节键`；先应用结构再校验正文路径。稳定 ID 与名称分离，未知路径、重复 ID、重复建议和超限输出拒绝落稿。
- `unresolvedIssues` 保留为同一 PRD 中的完整清单，最多 100 项，建议用稳定 Q 编号和模块/页面名称标注；未涉及问题保留。设计建议支持关联页面正文，仍只新增并由用户采纳。被删除页面的旧建议不能写入其他位置，可明确忽略。正式确认不能由模型输出触发。
- 后端保证结构、来源与修订一致性；正文是否准确体现用户意图和关联章节是否语义一致，仍由模型质量及人工定稿审阅决定。
- 本地模板只在空 PRD 中复制首段原文到交付范围，之后说明不执行语义改写。模板结果始终标注“未调用大模型”，不冒充真实模型生成。

## 模块和页面模板

管理系统模板参考 [人员管理 PRD 样板](prd-examples/personnel-management-prd.md) 提炼可复用结构，不把样板中的人员业务规则作为其他项目的默认要求。以下为共有的模块、页面结构；具体显示标题和定稿要求以文档绑定的模板版本为准。

- 模块包含目标范围、业务规则与关联影响、权限与数据范围、模块验收场景，以及有序页面列表。
- 页面类型支持列表、表单、详情、树形列表、日历、甘特图、关系图、自定义、首页、内容流和引导 / 步骤流程。三个内置模板都保留全部兼容类型，以便混合产品使用和切换后保留已有页面；新建选项顺序及默认类型随模板变化。列表展示字段和表单输入字段分别维护。
- 列表/树形列表要求说明入口、展示字段、搜索条件、排序分页、按钮操作、页面状态和验收。表单要求说明入口、表单字段与校验、交互联动、操作、状态和验收；不强制填搜索排序。
- 详情要求展示字段、操作、状态和验收；日历等其他类型要求展示元素和交互说明。已填写的可选章节在类型切换后继续显示，不丢弃旧内容。
- 界面支持添加、改名和移除模块/页面，全部共用自动保存与撤销。目录选择器可定位到模块或页面，同时切换左侧讨论焦点。必要章节采用写作提示，提示不作为已完成正文保存。
- 正文目前使用纯文本/Markdown 输入，不执行 HTML；历史、过期候选和 Markdown 下载保留整个模块页面树及问题清单。
- 新版整体说明要求背景、目标角色、范围、流程、公共规则、非功能和排除范围；全局异常与整体验收可按需补充，页面验收仍必需。未知内容可以保存草稿，定稿时再检查。
- 文档最多 30 个模块，每模块最多 30 个页面，单章节最多 10000 字符（旧全局章节保留原上限），总产物 JSON 最多 240000 字符。模型每轮最多 300 个正文补丁，超限失败保留原稿。

## 存量兼容

旧 JSON 未含 templateVersion/modules 时按旧版读取，延续正文和历史来源；已定稿文档保持原确认版本。已有草稿可以直接添加模块，首次添加或模型返回结构增量时升级为新版，未涉及的旧正文全部保留；不推断拆分旧正文。新版保存拒绝降级，防止旧客户端覆盖模块。此次复用现有 JSON 存储，不增加数据库迁移。旧 PRD 若存在未同步的需求变化，会加入核对原始资料的待确认提示。

仅有旧需求资料时，复制已明确的目标、范围和验收内容；未知章节留空，未解决问题进入文档问题清单，未采纳建议保留为独立建议。超长原文不截断冒充完整迁移，转为提示用户整理，原始资料继续可查阅。旧评审正文、建议决策、原始会话草稿、保存记录和基线都保留。

新模式不再接受旧 `REVIEW` / `GENERATE` 会话命令；旧页面应刷新。旧生命周期保存/生成接口不能要求新模式创建上游基线，重新评审接口拒绝新模式回退。既有未转换版本的历史管理能力保留用于兼容。

## API

前缀 `/api/alpha/workspace`，沿用现有统一响应。

| 路径 | 行为 |
| --- | --- |
| POST sessions/{id}/workbench/open | 打开并按需初始化同一 PRD / 转换旧会话 |
| POST versions/{id}/workbench/open | 版本入口复用最近会话 |
| GET sessions/{id}/workbench | 读取文档、建议、消息任务与真实状态 |
| PUT sessions/{id}/workbench | 双修订自动保存 `prd` |
| POST sessions/{id}/workbench/runs | `DOCUMENT` 或章节焦点的增量编辑任务 |
| POST sessions/{id}/workbench/suggestions | 显式 `ACCEPT` / `DISMISS` 建议 |
| POST sessions/{id}/workbench/prd/edit | 定稿后继续编辑 |
| POST sessions/{id}/workbench/prd/confirm | 人工确认当前已保存 PRD |

## 文档阅读与局部编辑（2026-10-14）

当前入口采用“目录—文档—会话”。会话路由默认收起全局项目导航，手动展开/收起后沿用用户在当前应用实例中的选择。PRD 目录按整体说明、模块说明、页面和全局约定切换；同一时刻只呈现当前范围。阅读时展示段落、列表和 Markdown 表格，不永久展示输入框。空章节集中到待补充区，点击展开或定位问题后可补充。

- 段落按块进入编辑；单一 Markdown 表格支持单元格、表头和行编辑。混有说明文字的表格使用原文编辑，避免转换丢失段落。所有正文通过 Vue 文本插值呈现，不执行外部 HTML。
- 局部输入直接更新唯一草稿并进入原有串行自动保存队列；完成编辑只返回阅读态，不增加第二次保存。页面切换不清空草稿。保存失败保留本地输入，仍使用双修订锁处理并发冲突。
- 新建模块/页面先填写名称，避免直接生成“未命名”占位模块。页面类型改变不删除已有正文；结构移除支持最近一次撤销及历史核对。
- 右侧会话可收起；点击章节“讨论”打开会话并设置稳定章节目标。已有长消息默认折叠；旧任务/旧流程的助手消息标为历史描述，原文仍可展开查阅。
- 新会话回复要求简短，不重复完整 PRD。后端在文档事务完成后生成保存/未应用状态；模型回答中的保存、应用、候选和定稿描述不作为业务状态。仅新增设计建议时明确“PRD 正文未修改”。原始模型回复保留在任务结果 `modelReply`，实际变化章节提供定位入口。
- 待确认、设计建议、历史版本和定稿检查按需从抽屉打开。定稿检查先等待自动保存，检查通过后仍需要用户点击“确认 PRD 定稿”。原型功能未接入。

### 问题关联契约

PRD JSON 新增可选 `issueLinks`：问题原文到稳定正文章节路径数组的映射。问题原文仍由 `unresolvedIssues` 管理，旧 JSON 缺少关联时按空映射读取，不根据文字猜测或批量改写旧数据。一个问题可关联业务规则、搜索条件及验收等多个章节。界面支持补充关联、定位和通过原会话回答；历史快照与 Markdown 下载都保留关联信息。

模型 Reply 的 `issueLinks` 为增量映射；null 不改动，空路径数组解除该问题的关联。关联必须引用最终文档中存在的问题和正文章节。已解决问题移除关联；删除页面仅清理失效路径，问题原文保留为未关联，避免悄悄丢失未决事项。模块或页面改名沿用稳定 ID，因此关联不变。该字段沿用已有 JSON 存储，不新增数据库迁移。

### 完整 PRD 预览

文档顶部增加“完整预览”，打开前等待自动保存完成，保存失败仍停留在编辑页保留输入。预览采用已保存草稿或不可变定稿的快照，后台更新不会改动正在阅读的内容；重新打开可取得最新版本。

完整预览使用大幅只读窗口，连续展示整体说明、全部模块与页面、公共规则和待确认事项。目录支持按章节、模块和页面跳转；窄窗口使用章节选择器。字段、搜索、按钮和表单表格沿用安全阅读渲染。问题保留关联规则名称，未填写的必要章节显示“尚未填写”，未采纳设计建议继续在独立面板维护。

预览中的 Markdown 下载使用当前预览快照，避免阅读与下载版本不一致。关闭预览保留原页面、编辑状态和位置；打开预览本身不产生历史版本或定稿，只有待保存的实际修改才进入原保存流程。

验证：前端 41 项测试及生产构建通过；相关后端 PrdDocumentsTest 回归通过。隔离 H2 浏览器验证完整目录、列表和表单表格、待确认关联、编辑后立即预览、关闭返回原页面、下载内容，以及 700 像素窄窗口的章节选择器。本次不涉及后端逻辑或数据库迁移。

### 预览问题定位与会话附件（2026-10-15）

完整预览中的待确认事项可点击。点击问题默认定位其第一条明确关联规则，顶部保留问题上下文，支持选择其他关联规则及“回到会话讨论”。返回后展开右侧会话、定位对应正文章节、预填问题，不自动发送；用户已有输入保留。无关联的问题回到全文讨论，不猜测位置。问题关联到空白可选章节时，完整预览和导出也保留该章节。若后台修改已解决或更名该问题，返回时提示重新查看最新 PRD。

### 单一定义源与兼容规则

唯一模板定义源为 `backend/src/main/resources/prd-templates/catalog.json`。后端 `PrdTemplates` 读取该资源用于公开目录、模型上下文、路径名称及定稿校验；前端在构建时导入同一个 JSON，用于编辑器、局部提示、页面类型、切换影响、待确认定位、历史、完整预览和 Markdown 导出。系统配置页通过目录 API 读取服务端版本列表。模板定义和原有 PRD 正文使用不同对象，提示文字不作为正文自动保存。

- `templateVersion` 继续表示 PRD 数据结构版本：`1` 是旧九章节结构，`2` 是模块 / 页面结构。它不是写作模板的版本，切换模板不修改这个字段。
- `templateId` 是写作模板的稳定身份，`templateRevision` 是该模板的精确发布修订。文档不能只存“当前最新模板”；未知或不完整的绑定被拒绝，不静默回落到其他版本。
- 历史 JSON 完全没有模板绑定时固定解析为 `management@1`。仅结构版本 `1` 且绑定 `management@1` 的文档沿用 `legacyGlobalSections` 的九章节名称；其他模板使用自己版本的章节标题。切换回 `management@1` 不丢弃已有正文，结构版本 `2` 也不会降回 `1`。
- 模板发布必须向 JSON 追加新的 `id + revision` 条目，不能原位覆盖已发布条目的名称、提示、顺序或必填规则，也不能删除仍被文档引用的版本。旧九章节定义同样保留。当前实现依靠这些不可变版本保留历史语义，不是将最新模板套用到旧快照。
- 前后端必须从同一份目录共同构建和发布；新增模板版本后重启后端并刷新前端，不能只替换后端资源而继续使用旧前端包。现有单 JAR 打包流程会同时构建前端；Gradle 的 `frontendBuild` 已将共享模板 JSON 纳入输入检测，模板变更会使旧静态产物失效。

本次绑定字段保存在既有 PRD JSON、任务快照及历史 JSON 中，不增加表或列，不新增 Flyway / DDL 脚本。动态模板编辑和发布管理留到第二步，当前没有实现；任意字段结构、脚本表达式及通用表单设计器不属于当前方案。

### 模板 API 增量

`GET /api/alpha/config/prd-templates` 返回统一 `{ code, message, data }`，其中 `data` 为 `{ legacyGlobalSections, templates }`。目录返回全部保留版本，由界面按模板身份选取最新版本展示卡片。每个模板包含 `id`、`revision`、`name`、`description`、`guidance`、`defaultPageType`、`globalSections`、`moduleSections`、`pageSections`、`pageTypes`、`requiredGlobalSections`、`requiredModuleSections`。章节定义是 `{ key, title, hint }`，页面类型定义是 `{ key, title, requiredSections }`。接口只读，不提供动态保存端点。

现有 `PUT /api/alpha/workspace/sessions/{id}/workbench` 的 `prd` 增加 `templateId` 和 `templateRevision`，仍携带原 `expectedRevision`、`expectedVersionRevision`。切换请求提交保留完整正文的同一份 PRD，不使用清空、重建或整份重新生成接口。`WORKBENCH` 任务上下文固定当次文档及其 `templateDefinition`，模型结果不具有变更模板绑定的权限；任务执行期间产生的新修订继续按原有并发规则处理。

### 用户流程与编辑边界

1. 在“系统设置 → PRD 模板”阅读内置或自定义已发布版本，点击“复制为自定义”，填写名称后建立独立草稿。来源版本明确固定，来源模板不变；未发布草稿不会出现在 PRD 模板选择中。
2. 草稿使用右侧抽屉，分为基本信息、整体说明、全局约定、模块、页面五组。每次仅展开一个章节的名称与提示输入，其他章节以摘要行呈现；组内切换保留输入，不把所有字段同时铺满。
3. 点击“保存草稿”只更新草稿；点击“发布”会先保存尚未提交的修改，再将该保存结果发布为不可变版本。保存失败不继续发布，输入保留。关闭未保存抽屉、ESC、导航和浏览器退出均保护修改。
4. 发布完成后可在 PRD 切换面板中选择自定义模板。已发布自定义模板通过“编辑下一版”建立新草稿；存在草稿时继续原草稿，不重复建立版本。查看旧发布版保持只读，新草稿以最近发布版为基础。

可编辑内容为模板名称、适用场景、默认页面类型，标准章节的显示标题、写作提示、组内顺序，以及非基础必填项。模板名称和章节标题最多 120 字符，适用场景和章节提示最多 2000 字符。写作提示作为编写参考，不自动成为 PRD 正文或已确认业务事实。

所有标准章节必须完整保留：9 个全局章节、4 个模块章节、11 个页面章节。章节键不可编辑、增加或删除；整体前四项与全局约定后五项分别允许排序，不能跨组移动。页面保留全部 11 种标准类型，UI 不开放类型增删或类型名称编辑。可为每一种页面类型独立调整必填项；章节名称与顺序对全部页面类型共用。

| 层级 | 不可取消的基础必填键 | 说明 |
| --- | --- | --- |
| 整体说明 | `background`、`objectives`、`scope`、`workflows` | 保留背景、目标、范围与流程的完整性底线 |
| 模块 | `overview`、`acceptance` | 保留用途范围与验收要求 |
| 每种页面类型 | `overview`、`states`、`acceptance` | 保留页面用途、状态与验收要求 |

界面将上述项标为“基础必填”，不能取消；后端也执行相同边界校验。其他标准章节可以设为必填或可选，不会因此从已有正文删除。模型总指导 `guidance` 继承复制来源，页面不提供原始提示词编辑；任意字段结构、脚本表达式和通用表单设计器不在本次范围。

### 定义来源、版本与已有文档

内置定义继续来自 `backend/src/main/resources/prd-templates/catalog.json`，前后端共同使用；自定义模板草稿和发布定义以普通 JSON 文本持久化到业务数据库。`PrdTemplateService` 统一按身份及修订解析内置或数据库已发布定义，草稿不能用于 PRD。发布目录返回全部保留修订，前端只注册已发布定义；同一 `id + revision` 不能被不同内容覆盖。

`templateVersion` 仍是 PRD 结构版本，`templateId + templateRevision` 才是文档绑定的写作模板。旧文档完全缺少引用时仍固定为 `management@1`。自定义模板保存或发布不主动修改当前 PRD、历史、定稿或进行中任务；编辑器、问题路径、预览、下载、模型上下文与定稿校验都按文档自身绑定解析。用户在 PRD 明确切换后，仍仅改变引用并保留全部正文、页面类型、稳定 ID 和问题关联。

自定义版本发布后，打开或刷新模板目录即可取得新定义，无需重启后端或重新构建前端。已有浏览器会话加载涉及未知自定义绑定的文档前先补齐已发布目录；PRD 切换窗口打开时刷新可选目录。内置 JSON 的代码变更仍需前后端共同构建发布，并遵守追加版本、禁止覆盖旧定义的规则。

### 并发与幂等

管理对象 `revision` 是并发锁，与拟发布版本 `draft.revision` 及 `latestPublishedRevision` 分开维护。保存、打开下一版草稿及发布命令携带最新 `expectedRevision`；修订冲突返回 `PRD_TEMPLATE_CONFLICT`，前端保留本地输入并要求明确重新载入，不能直接用旧锁覆盖新草稿。重新载入完成前冻结编辑输入，失败仍保留副本。

复制和发布携带 `requestId`。同一请求 ID 与同一参数重试返回原业务结果，不创建重复模板或版本；同 ID 不允许替换参数。已发布命令的重试，即使该模板后来又建立新草稿，也不能把新草稿再次发布。保存和开草稿没有独立幂等键，网络结果不确定时读取管理目录核对服务端锁和草稿，不能假设请求没有成功。

### 管理 API

统一前缀为 `/api/alpha/config/prd-templates`，响应沿用 `{ code, message, data }`。

| 方法与路径 | 输入与返回 |
| --- | --- |
| `GET /` | 返回 `{ legacyGlobalSections, templates }`；仅含内置和所有自定义已发布版本 |
| `GET /management` | 返回自定义 `Managed[]`；与 PRD 可选目录分开 |
| `POST /copies` | `sourceTemplateId`、`sourceTemplateRevision`、`name`、`requestId`；返回新建或幂等命中的 `Managed` |
| `POST /{id}/draft` | `expectedRevision`；打开下一版或返回现有草稿，返回 `Managed` |
| `PUT /{id}/draft` | `expectedRevision`、`configuration`；只保存草稿，返回 `Managed` |
| `POST /{id}/publish` | `expectedRevision`、`requestId`；发布已保存草稿，返回 `Managed` |

`Managed` 包含 `id`、管理锁 `revision`、`latestPublishedRevision`、可空 `draft`、`createdAt`、`updatedAt`。`draft` 沿用 `Definition` 结构，发布完成后通常为 null；幂等重试时以实际返回状态为准。

`configuration` 仅接受 `name`、`description`、`defaultPageType`、`globalSections`、`moduleSections`、`pageSections`、`pageTypes`、`requiredGlobalSections`、`requiredModuleSections`。章节和页面类型结构沿用第一步契约，服务器检查精确键集合、重复键、固定分组、标准类型名称及基础必填项。模板身份、发布修订和 `guidance` 不属于可编辑请求字段。内置身份拒绝开草稿、保存和发布操作，只能通过复制创建自定义身份。

业务校验错误为 `PRD_TEMPLATE_INVALID`，不存在为 `PRD_TEMPLATE_NOT_FOUND`，修订或幂等参数冲突为 `PRD_TEMPLATE_CONFLICT`；HTTP 分别使用 400、404、409。输入文本仍按纯文本展示，不执行 HTML 或表达式。

## 模板删除与恢复（2026-10-28）

自定义模板增加可恢复删除。删除仅改变模板的可选状态，不删除草稿、发布版本或任何 PRD；内置模板保持只读，不能删除或恢复。以下补充本节之前的历史实现记录。

### 用户操作与文档保留

“系统设置 → PRD 模板”默认展示正常模板；自定义模板详情提供删除动作，“已删除”目录提供只读查看和恢复。尚未发布过的自定义草稿同样可以删除和恢复。恢复沿用原模板 ID、发布修订及当前草稿，不复制出新模板，也不自动发布草稿。

删除后，该身份从正常管理卡片和 PRD 新选择列表隐藏，不能作为新复制来源，也不能继续编辑或发布模板草稿。模板输入尚未保存时不会因为删除而自动保存；已有未提交输入继续由原关闭和离开保护处理。来自其他窗口的删除会使旧管理写入被服务器拒绝，本地输入保留，需读取最新状态或先恢复模板。

已绑定同一 `templateId + templateRevision` 的 PRD 继续允许手工编辑、采纳建议、会话增量修改及定稿。目录、规则定位、待确认关联、完整预览、历史快照和 Markdown 下载仍按原精确版本解析。删除不更改正文、模块 / 页面 ID、页面类型、问题或模型任务上下文，也不自动改用其他模板。进行中的任务仍使用已固定版本；任务期间另有文档修订时，仍按原有机制保留未应用结果。

新建文档或其他已有文档不能新绑定已删除模板；同一身份改到另一发布修订，也视为新绑定。恢复后重新允许选择其已发布版本，原有文档不会自动升级到最新修订。

如果切换窗口打开后目标在另一窗口被删除，提交会被服务器拒绝。界面恢复切换前的有效模板引用并保留正文，可继续编辑或选择其他模板，不让自动保存队列一直停在失败状态。撤销涉及已删除旧绑定时，也保留有效引用和正文，不通过重新载入整稿来丢弃输入。

### 删除状态与接口

统一前缀继续为 `/api/alpha/config/prd-templates`，响应沿用 `{ code, message, data }`。

| 接口 | 当前返回或命令语义 |
| --- | --- |
| `GET /` | 返回 `{ legacyGlobalSections, templates, deletedTemplateIds }`；`templates` 保留全部已发布定义，删除身份单独列出 |
| `GET /management` | 返回全部自定义 `Managed[]`，增加 `deleted: boolean`，供正常 / 已删除目录分别展示 |
| `PUT /{id}/deletion` | 输入 `{ expectedRevision, deleted }`；`true` 删除、`false` 恢复，返回最新 `Managed` |

`deletedTemplateIds` 可以包含尚未发布、因此没有任何 `templates` 条目的自定义身份。前端不得把删除身份的定义从运行期精确版本目录移除，只过滤新选择；恢复也不修改不可变定义。草稿仍只存在管理响应中，不注册为 PRD 可引用的发布定义。

删除、恢复与开草稿、保存、发布共用管理 `revision` 和同一模板行锁。调用方提交最新 `expectedRevision`；并发改变使旧请求返回 `PRD_TEMPLATE_CONFLICT`，需核对服务器当前状态。已删除状态禁止新复制、编辑和发布，错误为 HTTP 409 / `PRD_TEMPLATE_DELETED`。内置身份仍由后端拒绝管理写入。删除 / 恢复命令不接受模板正文或新发布定义。

已有引用解析与新绑定校验分离：`resolve` / `forDocument` 保留已删除版本读取；统一会话及旧 PRD 保存入口在项目事务中比较服务端已有精确引用。只在首次绑定或引用变化时检查目标是否可选，并锁住自定义模板聚合，与删除操作串行化。客户端缓存或旧窗口不能绕过该校验。

复制幂等重试可能返回后来已删除的原模板聚合，界面应按返回状态进入已删除目录，不重新复制、不打开其编辑器；发布也不能通过旧请求重试恢复模板或发布新草稿。

### V10 迁移边界

新增 `V10__add_prd_template_deletion.sql`，前置为已执行 V9，内容为给 `prd_templates` 增加 `deleted BOOLEAN NOT NULL DEFAULT FALSE`。V9 保持原文件和校验和，不回填修改已发布定义、草稿或 PRD 绑定。增量使用 `ADD COLUMN IF NOT EXISTS`，已有删除状态不会因重复执行被恢复为 false；已有同名列但结构异常时仍需单独核查。

正常应用启动由 Flyway 执行缺失迁移：V8 数据库先 V9 后 V10，V9 数据库只执行 V10，已到 V10 的库校验后跳过。独立脚本 `backend/script/v0.1.0/v0.1.0-prd-template-deletion.sql` 与 V10 对齐；`v0.1.0-upgrade.sql` 按顺序包含 V9 + V10，前置 V1–V8，不是空库初始化脚本。通常不另行手工执行这些同内容脚本，避免业务结构与 Flyway 历史脱节；完整执行说明见 [数据库脚本说明](../backend/script/README.md)。

## 会话删除与回收站（2026-10-28）
