# 人员管理 PRD 样板

版本：0.1 草稿　｜　日期：2026-10-14　｜　整理：Andersen

人员管理用于查看和维护人员及资源的基础资料，并支持从钉钉单向同步人员信息。本样板覆盖人员列表、查询、排序、新增与编辑、同步操作、权限边界和验收场景，作为功能模块型 PRD 的审阅样例。

**审阅重点：先看第 3～5 节的页面与表单描述是否达到预期细度，再讨论第 10 节的业务问题。当前为草稿，未定稿。**

## 1 产品目标与范围

### 1.1 来源与规则状态

样板依据原始 v1.0 需求拆分的第 1.2 节“人员管理”，关联参考第 1.3 节“团队管理”、第 1.4 节“能力矩阵”、第 2.1 节“产品线管理”和第 4.2 节“任务管理”。

本样板使用三种标识，避免将新增设计当成已确认的业务要求：

| 标识 | 含义 | 使用方式 |
| --- | --- | --- |
| 原文要求 | 来源文档已经明确的内容 | 保留其原有含义；不代表本样板已整体定稿 |
| 设计建议 | 为形成完整页面提出的可评审方案 | 独立列在建议段落中，采纳后才纳入正式要求 |
| 待确认 Qxx | 会影响功能行为、数据含义或交付范围的未定问题 | 正文引用问题编号，第 10 节维护统一结论 |

本文件版本仅表示样板修订版本，不调整源文档的产品版本。源文档标题 v1.0.0 与修订记录 v1.1.0 的范围差异见 Q16。

### 1.2 目标

根据原文功能整理，人员管理承接以下工作：

- 通过列表和条件搜索查找人员资料。
- 新增或修改人员基础信息及部门、团队、产品线等关联信息。
- 维护人员类型与资源容量，为关联业务提供基础数据。
- 手动触发从钉钉单向同步人员信息。

具体操作角色和数据可见范围待确认，见 Q01。

### 1.3 本样板范围

| 范围 | 内容 |
| --- | --- |
| 原文要求 | 人员列表、六项查询条件、新增、修改、拉取人员信息、原文列出的十二项人员字段 |
| 本样板的设计建议 | 列表布局、分页与排序、表单控件、校验反馈、同步进度与结果展示 |
| 关联模块 | 部门、团队、产品线提供关联资料；能力矩阵和任务管理使用人员或资源信息 |
| 不在本样板展开 | 部门树维护、团队维护、产品线维护、能力绑定操作、任务排期算法、排班计划 |
| 未列入本次设计范围 | 删除、批量修改、导入导出、独立人员详情页；原文未提出这些能力 |

“未列入”仅说明样板边界，不代表最终产品永久排除这些能力。人员管理是否参与数据沙箱及其交互边界见 Q16。

### 1.4 术语

| 术语 | 当前含义 | 边界 |
| --- | --- | --- |
| 人员 | 原文模块名称，记录可能代表普通人员、外包团队或设备资源 | 暂沿用原名；是否改称“人员与资源”，见 Q02 |
| 人员类型 | 单选属性，原文举例为普通人员、外包团队、设备资源 | 完整枚举及是否可配置见 Q02 |
| 资源容量 | 同时可处理的任务数量，默认值为 1 | 原文例：外包资源容量 5 表示可挂载 5 个任务；计数边界见 Q06 |
| 拉取人员信息 | 从钉钉单向强制同步到本系统 | “强制”对应的覆盖字段、身份匹配和失败处理见 Q11～Q13 |

## 2 页面关系与操作流程

### 2.1 页面关系

原文要求人员首页采用普通列表并支持条件搜索，提供新增、修改、拉取人员信息三个操作入口。

**设计建议：** 菜单入口为“人员管理 → 人员管理”，进入人员列表。新增、修改使用右侧抽屉，避免离开当前查询上下文；同步结果使用独立结果面板。菜单命名及交互形式待确认 Q07。

```text
人员列表
├─ 设置查询条件 → 查询 → 查看结果
├─ 新增 → 填写人员表单 → 提交 → 更新列表
├─ 行内修改 → 回填人员表单 → 提交 → 更新列表
└─ 拉取人员信息 → 查看执行状态 → 查看同步结果 → 更新列表
```

上述打开方式、刷新规则和执行反馈属于设计建议，不增加审批步骤。

### 2.2 跨模块关系

| 关联对象 | 原文关系 | 本模块需要明确的边界 |
| --- | --- | --- |
| 部门 | 人员具有所属部门 | 单部门或多部门、能否无部门、包含下级部门的查询规则，见 Q04 |
| 团队 | 人员具有所属团队，团队可查看关联人员 | 一人多团队及关联维护入口，见 Q04 |
| 产品线 | 人员具有所属产品线，产品线可查看关联人员 | 一人多产品线及与团队、部门的联动，见 Q04 |
| 能力矩阵 | 能力可以绑定人员和等级，并提供人员视图 | 本样板不增加能力编辑入口；离职后的关联保留规则见 Q03 |
| 任务管理 | 任务关联执行人，自动指定人员时使用能力及等级 | 容量、类型、状态变化是否影响已有任务，见 Q06、Q14 |

## 3 人员列表

### 3.1 页面布局

**原文要求：** 普通列表展示，支持条件搜索。

**设计建议，待确认 Q07、Q08：** 自上而下为标题与说明、查询区、工具栏、列表和分页区。工具栏放“新增人员”“拉取人员信息”，每行放“修改”。默认不增加勾选列和批量操作。

### 3.2 查询条件

下表前两列为原文要求；控件、默认值和组合行为属于建议，明确写出的待确认项以第 10 节结论为准。

| 查询条件 | 原文要求 | 控件与交互建议 | 默认值建议及待确认事项 |
| --- | --- | --- | --- |
| 人员姓名 | 模糊搜索 | 输入框；忽略首尾空格，按包含关系匹配 | 默认空；匹配是否区分大小写见 Q09 |
| 在职状态 | 下拉选择 | 单选下拉 | 默认全部；完整枚举及默认是否仅在职见 Q03、Q09 |
| 部门 | 提供部门查询条件 | 部门树单选 | 默认全部；是否包含子部门见 Q04、Q09 |
| 团队 | 提供团队查询条件 | 可搜索的单选下拉 | 默认全部；候选范围及多选需求见 Q04、Q09 |
| 产品线 | 提供产品线查询条件 | 可搜索的单选下拉 | 默认全部；候选范围及多选需求见 Q04、Q09 |
| 人员类型 | 提供人员类型查询条件 | 单选下拉，显示类型名称 | 默认全部；完整选项见 Q02 |

**设计建议，待确认 Q09：**

- 点击“查询”或在姓名输入框按回车执行搜索；不同条件之间采用“且”关系。
- 修改条件后不立即请求，执行查询时回到第 1 页。
- 点击“重置”恢复默认条件、默认排序和第 1 页，并执行一次查询。
- 查询值“全部”表示该项不限制，不等同于“未关联”；如需查询未关联部门等情况，应增加单独选项。
- 从编辑返回保留查询条件；是否跨菜单或刷新页面保留条件，见 Q09。

### 3.3 列表字段

原文列出了以下十二项字段。表中的“展示建议”用于审阅，列顺序与默认可见性尚未定稿，见 Q08；每个字段是否可编辑另见第 4 节。

| 建议列序 | 字段 | 原文含义或要求 | 展示建议 | 待确认 |
| --- | --- | --- | --- | --- |
| 1 | 人员编码 | CODE 值 | 单行文本，长文本省略并可查看完整值 | 生成方式、唯一范围，Q05 |
| 2 | 人员姓名 | 人员姓名 | 单行文本；本样板暂不增加详情跳转 | 外包团队和设备是否共用名称字段，Q02 |
| 3 | 在职状态 | 存在此字段 | 文本标签，同时用文字区分状态 | 枚举、非人员资源是否适用，Q03 |
| 4 | 所属部门 | 存在此字段 | 显示部门名称 | 多部门及同名部门展示，Q04 |
| 5 | 所属团队 | 存在此字段 | 显示团队名称 | 多团队时的展开方式，Q04 |
| 6 | 所属产品线 | 存在此字段 | 显示产品线名称 | 多产品线时的展开方式，Q04 |
| 7 | 人员类型 | 单选；例：普通人员、外包团队、设备资源 | 显示类型名称 | 枚举、可否变更，Q02 |
| 8 | 资源容量 | 默认 1，表示可同时处理的任务数量 | 数值展示 | 范围、单位解释及适用类型，Q06 |
| 9 | 修改时间 | 存在此字段 | 显示年月日及时分秒 | 触发更新的操作、时区，Q08 |
| 10 | 同步时间 | 存在此字段 | 无同步记录时建议显示“未同步” | 成功时间还是尝试时间，Q11 |
| 11 | 创建时间 | 存在此字段 | 显示年月日及时分秒 | 时间格式和时区，Q08 |
| 12 | 人员 ID | 存在此字段 | 建议默认隐藏，保留为可选展示列 | 是否面向业务用户展示，Q08 |

**展示建议，待确认 Q08：** 列表右侧另设固定“操作”列，包含“修改”。人员编码至资源容量默认展示，三个时间字段作为可选列，人员 ID 默认隐藏；以上完整字段清单不等于要求默认同时展示所有字段。

无关联值建议显示“—”；未加载成功与无值需区分。长名称可悬停查看完整文本；时间格式建议统一为 `YYYY-MM-DD HH:mm:ss`，时区待确认。不得仅依靠颜色表达状态。

### 3.4 排序与分页

原文没有定义默认排序、列排序和分页。以下为**设计建议，统一待确认 Q08**：

| 项目 | 建议规则 |
| --- | --- |
| 默认数据排序 | 修改时间降序；时间相同时按人员 ID 升序，保证翻页顺序稳定 |
| 可操作排序列 | 人员编码、资源容量、创建时间、修改时间、同步时间 |
| 排序交互 | 同时仅启用一列的用户排序，支持升序、降序、恢复默认；同值时仍按人员 ID 升序 |
| 同步时间为空 | 升降序均放在有同步时间的记录之后 |
| 人员姓名排序 | 暂不提供；如需中文拼音排序，需明确中英文、数字混排规则 |
| 分页 | 默认每页 20 条，可选 20、50、100 条，显示总数 |
| 查询或页容量变化 | 回到第 1 页；单纯翻页保留查询和排序 |
| 新增成功 | 保留查询条件并回到第 1 页；新记录不符合条件时提示“新增成功，当前筛选条件下不可见” |
| 修改成功 | 保留查询、排序与当前页并刷新；若当前页已无数据，回到最近有效页 |

这里的“列序”只决定字段横向排列，“数据排序”决定记录纵向排列；资源容量和任务排期优先级不由列表排序决定。

### 3.5 按钮与操作

“新增、修改、拉取人员信息”为原文要求；“查询、重置”和以下位置、反馈为设计建议。角色权限统一见 Q01。

| 操作 | 建议位置 | 前置条件 | 操作行为建议 | 成功或失败反馈建议 |
| --- | --- | --- | --- | --- |
| 查询 | 查询区 | 有查询权限，条件有效 | 按当前条件获取第 1 页 | 成功更新结果；失败显示重试入口，保留条件 |
| 重置 | 查询区 | 有查询权限 | 恢复默认条件和排序并查询 | 更新结果 |
| 新增人员 | 工具栏 | 有新增权限 | 打开空白表单，资源容量预填 1 | 提交成功后关闭并刷新；失败保留输入 |
| 修改 | 每行操作区 | 有修改权限且记录可访问 | 打开表单并回填数据；受同步管理的字段按规则限制 | 成功后刷新；记录不存在或不可访问时提示并刷新列表 |
| 拉取人员信息 | 工具栏 | 有同步权限；数据模式允许，见 Q16 | 按第 5 节流程执行；不默认使用当前搜索条件作为同步范围 | 展示执行状态和结果；失败原因可读且支持按规则重试 |

权限不足建议隐藏入口；暂时不可操作时禁用并说明原因。具体权限划分和同步期间的禁用范围分别见 Q01、Q13。

### 3.6 页面状态

以下为**设计建议，待确认 Q07、Q13**：

| 状态 | 页面反馈 | 用户可执行动作 |
| --- | --- | --- |
| 首次加载 | 列表区域显示加载状态 | 等待；避免显示“暂无数据”造成误解 |
| 无任何记录 | “暂无人员信息” | 按权限展示新增、拉取人员信息入口 |
| 筛选无结果 | “未找到符合条件的人员” | 修改条件或重置 |
| 查询失败 | 展示失败提示；已有数据若保留，明确标记未刷新 | 重试；保留查询条件 |
| 表单提交中 | 提交按钮显示处理中并防止重复提交 | 等待结果 |
| 同步执行中 | 工具栏或结果面板显示处理中 | 按 Q13 确认后的规则限制重复同步 |
| 部分同步失败 | 区分成功和失败数量，展示可读原因 | 查看失败明细；按 Q13 重试 |

## 4 新增与编辑人员

### 4.1 表单字段

原文要求支持新增和修改，但没有规定表单字段的必填性、长度、默认值及可编辑性。以下为**表单设计建议**；除资源容量默认值 1、人员类型为单选外，新增的约束均待确认。

| 字段 | 控件建议 | 必填建议 | 新增建议 | 编辑建议及待确认 |
| --- | --- | --- | --- | --- |
| 人员编码 | 单行输入或只读文本 | 待确认 | 手动输入或自动生成待选，不同时假设两套机制 | 是否可修改、唯一性范围及长度见 Q05 |
| 人员姓名 | 单行输入框 | 是，待确认 | 默认空 | 可编辑性受同步规则约束；长度上限见 Q10、Q12 |
| 人员类型 | 单选下拉 | 是，待确认 | 默认不选，避免将设备默认为普通人员 | 是否允许变更及变更影响见 Q02、Q14 |
| 在职状态 | 单选下拉 | 依类型确定 | 默认值及设备适用状态待确认 | 状态流转与离职处理见 Q03 |
| 所属部门 | 部门树选择器 | 待确认 | 默认空 | 单多选、可选范围和无效关联处理见 Q04 |
| 所属团队 | 可搜索下拉 | 待确认 | 默认空 | 单多选及是否受部门影响见 Q04 |
| 所属产品线 | 可搜索下拉 | 待确认 | 默认空 | 单多选及与团队的联动见 Q04 |
| 资源容量 | 数字输入框 | 是，待确认 | 默认 1 为原文要求 | 建议正整数；能否为 0、上限及容量调低影响见 Q06 |
| 人员 ID | 不提供输入 | 不适用 | 建议由系统生成 | 建议只读；标识关系见 Q05、Q11 |
| 创建时间 | 不提供输入 | 不适用 | 建议由系统记录 | 建议只读；时间语义见 Q08 |
| 修改时间 | 不提供输入 | 不适用 | 建议由系统记录 | 建议只读；哪些操作会更新见 Q08 |
| 同步时间 | 不提供输入 | 不适用 | 未同步时无值 | 建议只读；时间语义见 Q11 |

### 4.2 校验与联动

以下为**设计建议**，约束取值依对应待确认项确定：

- 字段错误显示在对应输入项附近；提交校验不通过时定位首个错误，不清空其他输入。
- 姓名和编码去除首尾空格；若成为空字符串，按最终必填规则处理。姓名不建议要求唯一，是否允许同名见 Q05、Q10。
- 编码如要求唯一，提交时给出明确重复提示；仅在输入时检查不能代替提交时校验。
- 部门、团队、产品线在提交时重新检查是否仍可选；失效时提示重新选择，不静默改成其他关联。
- 修改类型时不直接清空其他字段；先按 Q02、Q03 明确哪些字段失效，再定义提示与处理。
- 容量小于当前占用时，是否阻止保存、仅影响新任务或触发重排，必须按 Q06 的结论处理。
- 钉钉维护的字段建议只读，并显示简短原因；是否允许本地覆盖以 Q12 为准。

### 4.3 提交与关闭

以下为**设计建议，待确认 Q07、Q14**：

1. “保存”校验并提交表单；成功后提示结果、关闭抽屉，按第 3.4 节更新列表。
2. 提交中阻止重复提交；失败时保留输入和错误说明，允许修改后重试。
3. 取消或关闭时，无改动直接关闭；有未保存改动时再提示是否放弃，不对每次正常保存增加确认。
4. 编辑期间记录若已被其他用户或同步任务更新，提示数据已变化并保留当前输入，不静默覆盖；重载与差异处理方式见 Q14。

本节描述的是人员管理样板中表单的提交方式，与 Agent 产品中 PRD 文档的自动保存机制是两种不同场景。

## 5 拉取人员信息

### 5.1 已明确的方向

**原文要求：** 用户可以通过按钮将钉钉人员信息单向强制同步到本系统。本样板不增加向钉钉回写能力。

同步身份匹配、覆盖字段和失败处理尚未明确；“强制同步”不能直接解释成覆盖所有字段或删除本地人员。

### 5.2 同步交互建议

以下为**设计建议，待确认 Q11～Q13**：

1. 用户点击“拉取人员信息”；按已明确的同步范围执行，不将当前列表筛选条件隐式带入同步范围。
2. 若同步包含覆盖本地修改或其他需用户判断的影响，执行前展示具体影响；是否需要确认取决于最终覆盖规则，不默认每次弹窗。
3. 执行中显示处理状态并防止重复触发。只有确有总量时才显示百分比，否则显示“同步中”。
4. 完成后显示处理记录总数，以及新增、更新、无变化、失败数量；四类按人员记录互斥统计，合计等于总数。
5. 失败记录展示可定位的人员信息、失败原因和可采取的动作，不显示凭证或技术堆栈。
6. 刷新列表时保留查询条件。部分成功与全部成功分别提示，重试范围按 Q13 处理。

### 5.3 同步数据边界

| 数据 | 原文能确定的内容 | 待确认 |
| --- | --- | --- |
| 钉钉人员与本地人员的对应关系 | 需要将钉钉资料同步到本系统 | 使用哪个稳定标识；本地已有同名或同编码人员如何匹配，Q11 |
| 姓名、部门、在职状态 | 人员资料包含这些字段 | 实际可同步字段及映射关系，Q12 |
| 团队、产品线、人员类型、容量 | 本系统存在这些字段 | 是否由本系统维护，同步时是否保留，Q12 |
| 本地新增人员 | 原文支持本地新增 | 后续钉钉出现对应人员时如何合并，Q11 |
| 钉钉中缺失或离职的人员 | 未定义处理方式 | 保留、标记离职或其他处理；不能据缺失直接推断删除，Q03、Q12 |
| 外包团队、设备资源 | 原文包含这类资源示例 | 是否完全排除在钉钉同步范围外，Q02、Q12 |
| 同步时间 | 原文存在该字段 | 记录最后成功同步、最后发现变更还是最后尝试的时间，Q11 |

## 6 业务规则与权限

### 6.1 原文业务要求

| 编号 | 要求 | 适用边界 |
| --- | --- | --- |
| R01 | 人员以普通列表展示，并支持条件搜索 | 字段与条件见第 3 节；排序、分页不是原文已定规则 |
| R02 | 支持新增和修改人员信息 | 表单约束及同步字段可编辑性待确认 |
| R03 | 人员类型为单选 | 原文类型为举例，完整枚举待确认 |
| R04 | 资源容量默认 1，描述同时可处理的任务数量 | 不等于每天可用工时；与并行任务的计数关系待确认 |
| R05 | 支持从钉钉单向强制同步 | 字段覆盖、匹配和删除语义待确认 |

### 6.2 权限设计建议

**待确认 Q01：** 建议分别控制查看、新增、修改、同步权限，同时定义数据范围。具有按钮权限不自动意味着可以操作全部人员。

| 能力 | 需要确定的权限边界 |
| --- | --- |
| 查看人员 | 全部人员、本部门、关联团队或其他范围；查询候选值是否遵循同样范围 |
| 新增人员 | 谁可以新增；可选择哪些部门、团队、产品线和类型 |
| 修改人员 | 可修改哪些记录与字段；是否允许本人维护部分资料 |
| 拉取人员信息 | 谁可以触发；同步范围是否独立于操作者日常可见范围 |

权限不足的操作应在服务端拒绝，页面隐藏入口只是交互反馈。该权限方案属于待确认设计建议。

### 6.3 跨模块影响

以下结论均**待确认 Q03、Q06、Q14**，不能由人员页面自行决定：

- 离职后已有任务、能力绑定、工时和排班记录如何保留，能否继续分配新任务。
- 调低容量后，已经安排的并行任务是否保持、提示冲突或重新排期。
- 变更部门、团队或产品线后，历史记录归属是否保持原值，以及查看权限是否立即改变。
- 普通人员改为设备或外包团队时，已有考勤、能力和任务关联如何处理。

## 7 非功能与异常要求建议

本节均为**设计建议，验收指标待确认 Q13～Q15**。

| 方面 | 建议要求 | 尚需明确的边界 |
| --- | --- | --- |
| 列表性能 | 分页查询，加载状态局部显示，不因同步阻塞整个页面 | 人员规模、并发用户数、响应时间目标，Q15 |
| 输入与显示 | 姓名、关联名称、失败说明按纯文本展示 | 字段长度和长文本布局，Q10 |
| 并发修改 | 避免编辑与同步互相静默覆盖，冲突时保留用户输入 | 冲突后的恢复方式，Q14 |
| 同步恢复 | 部分失败可定位；重试不应产生重复人员 | 重试策略、执行中关闭页面后的状态恢复，Q13 |
| 操作审计 | 建议记录新增、修改及同步的操作者、时间、结果和关键变更 | 可见范围、保存期限及是否需要审计页面，Q15 |
| 权限反馈 | 无权限、数据不存在和普通查询失败采用可理解的反馈 | 角色及数据范围，Q01 |

| 编号 | 前置条件与操作 | 预期结果 | 依赖 |

| AC02 | 使用人员姓名查询已知记录 | 支持模糊搜索并返回匹配记录 | 具体匹配语义 Q09 |

| 编号 | 前置条件与操作 | 采纳建议后的预期结果 | 依赖 |
| --- | --- | --- | --- |
