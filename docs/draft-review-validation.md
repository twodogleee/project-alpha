## 浏览器与打包运行验证

使用隔离端口 5179/18081 和 `/private/tmp/alpha-review-browser` 临时数据库，未写入默认开发 data 目录。

1. 使用示例创建客户管理项目，保存 v1，标明模板来源，生成需求均待确认。
2. 修改生成需求，确认第一项，新增人工需求，填写澄清回答，保存 v2。
3. 刷新后恢复项目 URL、正文、确认状态、人工新增项和保存版本。
4. 改写已确认正文后立即变待确认，下载被禁用；新建入口触发未保存提醒，选择继续编辑保留内容。
5. 保存 v3；读取历史 v1，原文、待确认状态与未回答问题保持不变。
6. 实际下载 `alpha-prd-v1.md` 并读取文件，内容对应 v1，包含来源、需求 ID、待确认事项与原始输入。
7. 两个浏览器窗口从 v3 编辑，第二窗口先保存 v4；第一窗口保存收到版本冲突，保留旧窗口编辑，不覆盖新版本。
8. 停止开发后端（预期 SIGTERM/退出码 143），用打包 JAR 重开同一临时数据库。
9. 直接访问 JAR 承载的页面，重开 v4，再确认并保存 v5，验证静态资源、同源 API 和重启持久化。
10. JAR 页面检查无前端 error/warn 日志。

界面截图在本次交付回复中提供。测试服务在验证结束后停止；测试项目不属于正式需求。
