# 可编辑、可确认、可保存的需求草稿

## 本阶段正式需求

用户已授权本阶段：先梳理需求与设计，再实现可编辑、可确认、可保存的需求草稿。

产品按单用户工作台规划。多人使用、团队协作、用户/团队/租户模型、项目成员及角色权限不纳入需求，也不列为待确认事项或后续必做项。

1. 输入项目名称和原始需求，生成草稿并保存；本地模板与模型结果始终标明来源。
2. 支持修改标题、概述，新增、修改、删除需求项；每项具有稳定 ID、来源、待确认/已确认状态。
3. 已确认需求的正文被修改时，立即回到待确认状态。确认只代表用户确认该项，不代表整个项目验收完成。
4. 支持逐条填写、修改澄清回答；回答不自动成为正式需求，可由用户手工增加需求。
5. 支持修改未接受的设计建议，接受或拒绝建议。接受后生成待确认需求，保留建议来源，需再明确确认。
6. 支持显式保存、项目列表、刷新后重新打开；已保存版本不可变，可查看历史版本。
7. PRD 从已保存版本生成，分别列出已确认需求、待确认需求、澄清问答、建议处理结果和原始输入。
8. 保存冲突必须提示，不能覆盖另一窗口已保存的内容；切换或离开时提醒未保存编辑。

## 设计建议与本次实现选择

- 初版使用 H2 文件数据库；按用户后续要求切换为本机 PostgreSQL，参考 Zero 的 MyBatis Plus 技术与配置。连接从后端私有配置或环境读取，Alpha 使用独立 schema。
- 每个项目先维护一份需求草稿；每次有效保存产生一个不可变快照版本。暂不提供历史恢复或合并。
- 使用 MyBatis Plus、事务和 revision 乐观并发控制，项目当前状态与版本快照一起提交；Flyway 管理表结构迁移。
- 保存正文修改与确认是两个明确动作；修改已确认正文的这次保存会强制取消确认，后续保存才可确认。
- 已接受建议保留原文及关联需求，不允许撤销接受或删除关联需求；需求正文仍可继续编辑。
- 原始输入与生成来源保存后不可修改；重新分析创建新项目，避免覆盖人工评审结果。
- 旧的单次分析 API 继续保留；新页面使用项目 API。

## 待确认事项（不阻塞本阶段）

- 历史版本恢复与需求评论。
- 澄清回答是否需要交给模型重新分析，以及如何保留人工修改。
- 多草稿、多次生成的版本分支与合并规则。

## 明确排除

本阶段不接入模型付费验证、多轮聊天、Graph 检查点恢复、RAG、SSE、原型、DOCX/PDF、认证、删除项目及线上部署。真实模型代码保留，未验证模型效果不能声明已验收。

多人使用与团队协作明确排除在产品需求规划之外。保留 revision 冲突保护，用于同一用户多个窗口编辑时防止误覆盖。

## 验收标准

1. 创建 demo 项目后，生成版本 1，所有生成需求均待确认，页面和 PRD 显示模板来源。
2. 编辑需求、增加需求、确认、填写回答后保存，刷新/重启应用可读取相同结果及稳定 ID。
3. 修改已确认正文后，该项回到待确认；其他已确认项不受影响。
4. 接受建议只能生成一个待确认需求，反复保存不重复生成；不能伪造来源或跨项目引用 ID。
5. 每次保存当前版本递增，旧版本正文与 PRD 保持不变。
6. 两个窗口同时编辑时，旧 revision 保存返回 409，失败不改变当前状态和历史。
7. 未保存编辑不会进入 PRD；页面提示未保存，下载按钮在有编辑时禁用。
8. 输入校验、未知项目、版本冲突和存储失败均返回安全错误；不展示外部 HTML，不输出密钥。
9. 后端业务/API/持久化测试与前端构建通过，浏览器验证创建、保存、重开、历史和导出。
