## 桌面浏览器与实际 JAR

使用独立 18081 服务和随机 `alpha_lifecycle_smoke_*` schema，建立合成“客户运营 · 生命周期验收”产品与“一期 · 客户导入”版本。没有修改用户开发 schema、模型配置或启用选择，所有浏览器生成均为 demo。

实际完成：

1. 手工定义版本和范围，创建结构化需求、验收标准、阻塞问题与设计建议。
2. 接受建议并保存后新增第二项待确认需求；阻塞问题未解决时不能确认基线。
3. 保存正文和验收标准，再逐项确认；问题填写结论并标为解决，基线门槛通过。
4. 人工确认评审基线进入 PRD；评审和范围受冻结规则保护。
5. 本地模板生成 PRD 候选，候选不自动保存；明确应用、保存后，待确认事项仍阻止定稿。
6. 人工补充流程、业务规则、异常、边界与排除范围，处理待确认事项后保存。
7. 未保存 PRD 切换路由触发离开保护，继续编辑保留输入。
8. 两窗口编辑同一 PRD，旧窗口保存发生 409，本地输入保留，明确放弃并重新载入后读取新文档。
9. 人工确认 PRD 基线进入原型等待，版本仍 ACTIVE；PRD 和评审只读，不能伪装完成交付。
10. 下载已确认 PRD，核对文件中的基线 ID、确认标识和正文，不含旧窗口未保存输入；该测试下载已移至临时验证目录。
11. 基线历史包含完整评审、PRD 和上游引用。记录原因重新评审后，旧 PRD 保留，旧基线仍可查看。
12. 修改需求撤销该项确认，重新确认评审产生新基线；旧 PRD 显示需要同步并禁止确认。
13. 明确采用新基线、人工合并异常路径、保存，再次确认 PRD；新旧确认链并存，变更原因可从“需求变更记录”查看。
14. 最新 JAR 重启、刷新恢复评审和 PRD 保存编号、当前基线、旧候选与阶段状态。
