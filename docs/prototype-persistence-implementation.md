# 原型 P3 业务持久化实现

日期：2026-10-29。作者：Andersen。

本文保留 P3 交付时的范围与验证记录。P4 已继续接入真实执行适配器，当前可用条件、模型与 Worker 链路见 [P4 实现说明](prototype-generation-implementation.md)；下文“执行器尚未接入”描述 P3 单独交付时的状态。

本轮对应 [第一阶段设计](prototype-phase-one-design.md) 的 P3：原型聚合、完整来源快照、不可变修订、通用任务扩展、候选应用、文件对象引用和中断恢复已接通。P1/P2 的模板与 Worker 保持独立，业务库不使用其 `current.json` 作为当前版本真值。

P4 生成执行器尚未接入。默认环境调用生成接口会返回 `503 / PROTOTYPE_RUNNER_UNAVAILABLE`，且不创建聚合、来源、消息或任务。自动测试通过显式合成执行器驱动完整事务，所有结果标记 `synthetic / test-fixture`，没有调用模型，也不将人员样板自动绑定任意 PRD。P5 工作台原型页和 P6 恢复、人工确认、导出接口继续后置。

## 数据与事务边界

Flyway V13 新增六张表，沿用字符串 UUID、`BIGINT` 修订、UTC 时间和 TEXT JSON：

| 表 | 当前职责 |
| --- | --- |
| `prototypes` | 每个 PRD 文档一个聚合，固定模板、聚合锁、下一修订序号和当前修订指针 |
| `prototype_sources` | 不可变的完整 PRD、背景、精确写作模板定义、选定范围和规范指纹 |
| `prototype_revisions` | 验证通过的不可变源码/静态对象引用、业务清单、检查记录、来源和生成模式 |
| `prototype_run_details` | `workspace_runs(kind=PROTOTYPE)` 的操作、输入锁、执行令牌、阶段、心跳和应用状态 |
| `prototype_commands` | 已实现 `APPLY` 幂等结果；`RESTORE` 存储契约预留给 P6 |
| `prototype_confirmations` | 人工确认存储契约；本轮不提供确认写入口，也不会自动创建确认 |

复合外键保证文档与项目、原型与来源/修订/任务同属一个业务聚合。确认来源只能是同文档 PRD 定稿；原型任务扩展只能关联 `PROTOTYPE` 任务。一个任务最多封存一个结果，同原型修订序号唯一。来源、修订、确认和控制命令没有仓储更新入口。

所有业务变更继续使用项目根行锁。PostgreSQL 部分唯一索引限制同项目最多一个活动 `workspace_runs`；H2 使用等价生成列索引测试。旧 `version_prd_runs` 与新任务的跨表互斥在同一个项目锁内检查，CHAT、DRAFT、WORKBENCH、旧 PRD 和原型提交均采用同项目限制。

1. 提交先验证稳定归属和读取资格，再按会话请求 ID 查幂等。相同完整命令返回原任务，不因当前正文、模板、锁或执行器状态变化而再执行；同键不同命令返回 409。
2. 新命令检查写入资格、执行提供方、活动任务及各自修订锁，原子保存聚合、来源、任务扩展和用户消息。提交后才派发执行。
3. 受信适配器领取一次执行令牌。编译、浏览器检查及文件验证在数据库事务外完成；没有公开 HTTP 完成回调或客户端路径输入。
4. 完成前后均检查任务状态和令牌。短事务中保存不可变修订、当前指针、任务终态和助手消息。
5. 原型基准、文档/PRD锁或项目修订在执行期间变化时，成功结果保留为 `CONFLICT` 候选，原当前稿不变。纯编辑继续保留原来源快照，来源的新鲜度独立展示。
6. 应用候选先按对象身份重验文件，再锁项目复查幂等、归属、当前锁及来源。PRD 或背景已变化的候选拒绝强制应用，要求先同步或重新生成；只有显示名称等非输入变化时可以按新锁显式应用。

文件已封存而数据库提交失败时，仅可能留下未引用对象。失败任务、无变化任务和中断任务不会生成假修订，也不改变当前指针。相同应用请求重传返回原命令结果，不重复更新指针。

## 来源与范围契约

既有 PRD 的页面 ID 只在模块内部唯一，因此范围、目标、覆盖和页面指纹采用复合身份。没有把现有 PRD 页面 ID 改成全局唯一，也不按标题或数组位置识别页面：

```json
{
  "mode": "SELECTED",
  "pageRefs": [
    {"moduleId": "personnel", "pageId": "list"},
    {"moduleId": "orders", "pageId": "list"}
  ]
}
```

新输入的 `ALL` 携带空 `pageRefs`，服务端展开为固定有序清单；冻结快照中的 `ALL` 包含这份清单。编辑可重用原冻结范围，但不能暗中增加或删除页面。一次支持 1–10 个 LIST / FORM / DETAIL 页面；不存在、重复、超量和不支持类型明确拒绝，不静默截断。

快照包含完整 PRD，即使只选择一个模块也不丢掉其他模块原文。写作模板按 PRD 绑定的精确版本解析，不采用当前默认版本；待采纳设计建议不混入正文。`GENERATE / SYNC_PRD` 冻结草稿或当前有效定稿；`EDIT` 必须引用当前原型的已有来源。

规范化版本为 `sha256-canonical-json-v1`：对象键排序，数组顺序和正文空白保留，采集时间和并发锁不进入内容摘要。选中页面、其模块规则、全局正文及背景变化返回 `STALE`；其他页面变化且没有充分依赖证据时返回 `REVIEW_REQUIRED`。重新开放编辑的旧定稿不能继续作为当前有效确认依据。项目显示名称变化本身不改变输入语义，但运行期间项目修订变化仍保守保留候选。

## 文件与来源标识

`PrototypeArtifactStore` 从配置 `alpha.prototype.artifact-root` 读取，默认是仓库根下的 `data/prototypes`。只接收 64 位内容身份，验证 `artifacts/{id}/artifact.json` 的原始字节摘要、完整静态/源码/截图树、每个文件的大小和 SHA-256、路径类型与符号链接限制，以及非空的全部 PASSED 检查。损坏、缺失、额外文件或失败检查均返回 `PROTOTYPE_ARTIFACT_UNAVAILABLE`，不透传底层磁盘异常。

业务库只存相对对象键和摘要，不存宿主绝对路径；公开任务视图不返回上下文、执行令牌、完整源码或原始诊断。`templateDigest / sourceDigest` 按格式验证并随不可变 manifest 固定记录，未重新计算 Worker 的汇总树摘要；文件完整性通过 manifest 本身及各文件实际摘要重新核验。

封存模式必须是三种明确组合之一：`demo / trusted-fixture`、`synthetic / test-fixture`、`live / model`。完成事务再次要求产物模式与领取任务时的模式一致，样板或合成对象不能登记为真实模型结果。P3 测试中的 `live / model` 仅验证标签拒绝规则，不代表模型调用证据。

## 任务中断与父对象状态

服务启动由统一工作空间恢复入口将旧原型任务及扩展令牌共同置为中断，不安排任何自动重试。心跳和排队等待上限均为 2 分钟，全任务总预算为 15 分钟，新心跳不能延长总预算。领取、心跳和完成会即时检查期限；后台每 30 秒回收过期业务租约，后续旧 Worker 回调不能再写修订。P4 执行适配器仍负责实际进程取消和定期心跳；这里的持久化不是 Graph 检查点恢复。

删除文档隐藏原型读取入口，但保留来源、修订及文件引用；恢复文档后继续访问原聚合。删除一个共享会话不会删除其他会话所用原型。归档或取消对象只读；活动任务参与项目、会话和文档现有删除/归档/取消保护。完成与无变化回调也复核父对象资格。

直接 PRD 的“是否开放编辑”使用当前定稿指针判断；进入 `PROTOTYPE` 后继续编辑仍保留阶段里程碑。后端保存、会话落稿与前端最小编辑门槛已同步，旧 REVIEW 流程保持原规则。本轮没有增加工作台原型操作页面。

## 已接入接口与 P4 对接

统一前缀 `/api/alpha/workspace`，继续返回 `{code,message,data}`：

| 方法与路径 | 当前行为 |
| --- | --- |
| `GET versions/{id}/prototype` | 原型不存在时返回 EMPTY，不创建生命周期或会话 |
| `POST versions/{id}/prototype/runs` | 完整幂等提交契约；执行提供方可用时返回 202，默认未接入返回 503 且无副作用 |
| `GET runs/{id}` | 通用状态附加 `prototype` 安全进度，包含阶段、结果修订和应用状态 |
| `GET versions/{id}/prototype/revisions` | 50 条有界历史分页，包含当前稿与候选 |
| `GET versions/{id}/prototype/revisions/{revisionId}` | 固定修订、完整冻结正文、来源新鲜度与检查记录 |
| `POST versions/{id}/prototype/apply` | 按精确修订和来源任务显式应用候选，记录独立幂等结果 |

提交字段以 `PrototypeContracts.Submit` 为准：会话、请求 ID、操作、四种预期锁、当前基准、固定模板、来源、范围、讨论目标、输入与可选重试来源。首次原型锁为 0；失败后空聚合仍存在，需要使用它的实际锁。任务 `draftRevision` 保留 PRD 产物聚合锁含义，原型锁位于任务扩展中。

P4 实现一个 `PrototypeExecutionGateway` 并保持以下顺序：事务后 `dispatch(runId)` → `claim` 固定来源和执行令牌 → 周期 `heartbeat` → 模型/Worker 在事务外执行 → 封存对象 → `complete`。异常通过安全错误分类调用 `fail`；确认没有变化时调用 `completeUnchanged`。不可用检测不能调用模型；派发异常会终结任务，避免留在 QUEUED。模型生成器不能直接更新实体、当前指针或调用旧 DRAFT 分支。
